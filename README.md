## «Мой баланс» v0.7.16 — самостоятельная настройка нормы калорий

- Исправлена неудобная ручная правка суточной нормы. Теперь на вкладке **«День»** в карточке энергии есть компактная кнопка **«✎ Норма»**, а в **«Профиль → Мои ориентиры»** — **«✎ Изменить норму калорий»**. Обе открывают понятное окно с обычным цифровым полем и отдельным «Сохранить».
- Число можно вводить через Android-клавиатуру без взаимодействия со стрелками `SpinBox`. Значение проверяется на диапазон **1000–5000 ккал**, неверный ввод не закрывает окно и не перезаписывает прежние настройки. Это технический диапазон ввода, **не рекомендация** снижать питание до 1000 ккал.
- В **«Профиль → Настройки и анкета»** прежнее поле суточных калорий также заменено на текстовое. Предварительный расчёт калорий для завтрака/обеда/ужина/перекуса обновляется при изменении числа.
- На последнем шаге **анкеты** ориентир теперь тоже вводится обычным числовым текстом и сохраняется вручную, даже если отличается от предложенного расчёта. Пересчитывать анкету ради очередного изменения нормы не нужно.
- Хранилище применяет изменения атомарно: при ошибке записи предыдущая норма восстанавливается. Пользовательские записи питания, вес, профиль, распределение долей и бонусные очки при смене суточных калорий не меняются.
- Автотест `godot/tests/calorie_goal_edit_test.gd` проверяет сохранение после перезапуска, ввод на трёх страницах, отбрасывание ошибочного числа, перерасчёт целей приёмов пищи и откат при ошибке сохранения.
- Android `versionName=0.7.16`, `versionCode=33`, прежние пакет и ключ подписи. Перед обновлением рекомендуется экспортировать JSON-резервную копию и **не удалять** предыдущую версию.

## «Мой баланс» v0.7.10 — проверка параметров при расчёте калорий

- Исправлена потенциально опасная ошибка интерфейса первого запуска: приложение **больше не подставляет примерные возраст, рост и текущий вес** как будто это данные пользователя. При первом заполнении эти поля остаются пустыми и обязательны.
- Перед расчётом требуется ввести точные возраст, рост и **текущий вес**. Поля принимают только числовые значения, рост и вес допускают десятичную точку или запятую. Незаполненные и неверные значения не позволяют перейти дальше.
- На втором шаге анкеты теперь крупно показаны использованные в расчёте **возраст, рост, текущий вес и вариант формулы**. Пользователь может проверить их до сохранения и вернуться на первый шаг.
- Добавлен отдельный регрессионный тест реальных параметров: **28 лет, 170 см, 88 кг, женская формула, низкая активность** должны дать ≈1642 ккал расхода покоя, ≈1970 ккал для поддержания и ≈1770 ккал при небольшом дефиците; **1538/1380 ккал для этих данных ошибочны**.
- Уравнение Миффлина — Сан Жеора оставлено прежним: ошибка была в автоподстановке примерных данных и отсутствии явной проверки, а не в формуле. Сохранили возможность установить индивидуальную суточную норму вручную.
- Настройки и данные из v0.7.9 сохраняются; существующие пользователи могут заново проверить свои параметры в «Профиль → Настройки и анкета → Моя анкета · пересчитать норму».
- Android: `versionName=0.7.10`, `versionCode=27`; не удалять приложение перед обновлением, сначала рекомендуется экспортировать JSON-резервную копию.

## «Мой баланс» v0.7.9 — компактные страницы и стартовая анкета

- На **чистой установке** появляется короткая анкета из двух экранов: имя, возраст (для взрослых 18+), рост, текущий вес и коэффициент формулы; затем обычная активность, цель (сохранить/постепенно снизить/набрать вес), желаемый вес и **редактируемый ориентир калорий**.
- Автоматическая оценка рассчитывается по уравнению **Миффлина — Сан Жеора** для взрослых (10 × кг + 6,25 × см − 5 × возраст + коэффициент −161 или +5), умножается на стандартный коэффициент активности 1,2/1,375/1,55/1,725. Для постепенного изменения веса используется небольшая поправка до 10%, не более 300 ккал; предусмотрен защитный порог для низкой калорийности. Это лишь статистическая оценка, а не назначение диеты. Можно не выбирать формулу и задать калории вручную.
- Приложение не меняет расчёт без подтверждения. Анкета и выбранные калории сохраняются атомарно вместе с именем и ориентиром веса. ## Android (v0.4.0)

Добавлена Android-оболочка (`app/`) поверх офлайн-дневника. Нативная версия работает в WebView на локальном `https://appassets.androidplatform.net/assets/index.html` через AndroidX WebViewAssetLoader, поэтому сетевой доступ для дневника не требуется.

В Android-версии для экспорта JSON используется системный выбор места сохранения (Storage Access Framework); импорт работает через системный выбор файла. Данные остаются локальными на устройстве, а перенос из браузера требует **вручную экспортировать JSON из браузерной версии и импортировать его в APK**: браузер и приложение не разделяют localStorage.

Данные автоматически между приложениями не синхронизируются; перенос требует ручного JSON-импорта. При копировании JSON в системный буфер обмена он может стать доступен другим приложениям.

### Сборка Godot Android APK через GitHub

Workflow: [Godot Android APK](.github/workflows/godot-android.yml).

Пайплайн скачивает Godot 4.6.3 и соответствующие export templates, настраивает Android SDK 35 и debug keystore, валидирует проект через headless editor и экспортирует `godot/build/MyBalance-debug.apk`. Артефакт успешного запуска называется `MyBalance-Godot-Android-APK`.

**Текущий статус:** [run #44471851233](https://github.com/Domenklay/My_balance/actions/runs/44471851233) завершился `failure` **до назначения GitHub runner, с 0 выполненных шагов**. Поэтому фактическая сборка, корректность GDScript в Godot и установка на телефон ещё не проверены, готового APK нет. Требуется устранить ограничение запуска GitHub-hosted runners в настройках Actions/биллинга этого приватного репозитория либо выделить self-hosted runner и изменить `runs-on` для него.

Для локальной сборки при установленном Godot 4.6.3, Android SDK и экспортных шаблонах:

```bash
godot --headless --editor --path godot --quit
mkdir -p godot/build
godot --headless --path godot --export-debug "Android" godot/build/MyBalance-debug.apk
```

Проверяйте apk на тестовом устройстве прежде чем доверять хранению важных записей.
